从 SEQ 到 PIPE：一条 Y86-64 指令的一生，与五条指令的同生共死

上半场（①–⑤）拆解顺序处理器 SEQ：取指 → 译码 → 执行 → 访存 → 写回 → 更新 PC，逐个搞懂 valA/valB/valE/valM 这些信号和每阶段的 HCL 控制逻辑。下半场（⑥–⑦）进入流水线：算清延迟与吞吐的账，再亲手逐周期推动一台带转发、会停顿、能冲刷错误指令的 PIPE，看懂数据冒险、加载/使用、分支预测错误和 ret。内容对应课件《4.3 顺序执行的处理器》《4.4 流水线的实现》与 docs/04-处理器体系结构.md §4.3–4.4。

⑤ 控制逻辑 HCL SEQ 的大脑：每个阶段怎么选、怎么使能

硬件单元是肌肉（内存、ALU、寄存器堆，存数据/做运算），控制逻辑是大脑（HCL 描述的多路选择与使能信号，决定数据从哪来、往哪去、要不要动）。四个标签页覆盖考试要考的四组控制逻辑，全部提炼自课件。

⑥ 流水线原理 像洗车流水线一样重叠执行指令

洗车的三个姿势：顺序（一次只能洗一辆）、并行（多条流水线同时洗）、流水化（一条线，冲洗/打蜡/烘干三站同时各有一辆车）。处理器流水线同理：不减少单条指令的延迟，甚至因为加寄存器还略增，但吞吐量大幅提升。拖动滑杆，亲手算一遍课件的经典数字。

📌 两大局限（课件原话）：① 延迟不一致——吞吐量由最慢阶段决定（150/50/100ps 的三段，时钟只能取 170ps，吞吐掉到 5.88 GIPS），把逻辑均分成等延迟阶段是严峻挑战；② 阶段不能无限深——寄存器开销占比 1/3/6 级分别为 6.25%/16.67%/28.57%。练习 4.29：延迟 = 300 + 20k ps，吞吐 = 1000/(300/k + 20) GIPS，k→∞ 时吞吐上限 = 1000/r = 50 GIPS，而延迟→∞。
💡 为什么必须加流水线寄存器？A、B 两段现在并行执行的是不同指令：B 需要的中间结果是上一周期 A 产生的，必须先存进阶段间寄存器。SEQ 的根本缺陷正是反过来：时钟要等一条指令走完全部六阶段（含访存），硬件单元只在周期的一小部分时间里被使用。

⑦ 冒险实验室 逐周期推动一台真正的 PIPE

流水线图是一种时序图：行=指令，列=时钟周期。下方模拟器里 ●气泡=被注入的空操作，划线格子=被冲刷的错误路径指令，译码格上的小箭头=转发来源；右侧解说当前周期流水线控制逻辑做了什么。选场景 →「下一周期」推进。部分场景可关闭数据转发对比气泡数量变化。
