四种"不合法"模式，答题时按这个顺序检查：
① icode 越界：首字节高 4 位为 C~F（如 C 序列的 f0）→ 连长度都无法确定，解码只能到此为止；
② 寄存器槽出现 F：F 只允许出现在 irmovq 的 rA 槽和 pushq/popq 的 rB 槽，其他位置都是非法（如 E 序列 a0 f0）；

图 4-6 · Sum 函数计算一个整数数组的和（相同的调用模式）

C 原型：long sum(long *start, long count)，start 在 %rdi，count 在 %rsi。

sum:
    movl $0,%eax       # sum = 0
    jmp .L2            # Goto test
.L3:

    addq $8,%rdi       # start++

    irmovq $1,%r9      # Constant 1
    xorq %rax,%rax     # sum = 0
    andq %rsi,%rsi     # Set CC
    jmp test           # Goto test
loop:
    mrmovq (%rdi),%r10 # Get *start
    addq %r10,%rax     # Add to sum
    addq %r8,%rdi      # start++
    subq %r9,%rsi      # count--
test:
    jne loop           # Stop when 0
    ret                # Return

x86-64 写法Y86-64 只能这样写原因

B0 · 条件传送指令 cmovXX 4.1 节 · 练习题 4.6 的主角

cmovXX rA, rB 的语义只有一句话：条件成立，才把 rA 的值复制进 rB；不成立则 rB 保持原值。它是"带开关的 rrmovq"——rrmovq 就是 fn=0（条件恒成立）的特例。家族一览（与 jmp 家族共用同一张 fn 条件表）：

首字节20212223242526
指令rrmovqcmovlecmovlcmovecmovnecmovgecmovg
条件恒成立≤<＝＝≠≥＞
  • 格式：2 字节 = 首字节（icode 2 : fn）＋ 寄存器字节 rA:rB。rA 是源、rB 是目的；只能寄存器到寄存器，不能碰内存（碰内存的是 mrmovq / rmmovq）。
  • 只读条件码，不写（见附录 3.4）：条件看的是"最近一次 OPq"留下的 ZF / SF / OF。硬件判定fn 表那一列的组合，如 cmovg ⇔ ZF=0 且 SF=OF。同一个 fn，接在 icode 2 上是 cmovXX、接在 7 上是 jXX——24 = cmovne，74 = jne。
  • 为什么存在：分支（jXX）在流水线上可能因预测错误付出十几周期的代价（第 3 章 3.6.6 条件传送）；cmov 把"跳不跳"变成"写不写"——无论条件真假都固定 1 条指令，没有控制冒险。编译器处理三元表达式、abs、max 时常用。代价：两个分支的值都得先算出来（所以 4.6 里 −x 也要先算进 %r11）。

小演算器：场景取自练习题 4.6——刚执行完 xorq %r11,%r11 和 subq %r10,%r11（r11 = 0−x，条件码来自这次减法），接着轮到 cmovXX %r11, %r10。改 x 和条件，看 %r10 会不会被替换：

硬件不看"−x > 0"这种数学式，它看减法结果 (0−x) 的 ZF / SF / OF 组合（fn 表那一列）。与 4.5 对照记忆：跳转版 jle 判断的是"保持不变"的情况（x≥0 时跳过替换），传送版 cmovg 判断的是"需要替换"的情况（x＜0 才写）——同一事实，条件互补。

练习题 4.5 条件跳转版 absSum

修改 sum 函数的 Y86-64 代码（图 4-6），实现函数 absSum，它计算一个数组的绝对值的和。在内循环中使用条件跳转指令。

参考解答与讲解

补的知识点：|x| ＝ x≥0 取 x，x＜0 取 −x；而 Y86-64 没有 neg，取负只能用 0−x。条件码恰好由做减法的 subq 顺便设好：

sum:
    irmovq $8,%r8        # Constant 8
    irmovq $1,%r9        # Constant 1
    xorq %rax,%rax       # sum = 0
    andq %rsi,%rsi       # Set CC（count=0?）
    jmp test             # Goto test
loop:
    mrmovq (%rdi),%r10   # r10 = *start
    xorq %r11,%r11       # r11 = 0
    subq %r10,%r11       # r11 = 0−x = −x，同时设置 CC（结果 = −x）
    jle keep             # −x ≤ 0 ⇔ x ≥ 0：r10 已经是 |x|，跳过
    rrmovq %r11,%r10     # x < 0：r10 = −x = |x|
keep:
    addq %r10,%rax       # sum += |x|
    addq %r8,%rdi        # start++
    subq %r9,%rsi        # count--
test:
    jne loop             # Stop when 0
    ret                  # Return

三种情况验证（条件 jle 作用在减法结果 −x 上）：

xr11 = 0−xjle（−x≤0）r10 最终
5−5成立 → 跳过替换5 ✓
−55不成立 → 执行 rrmovq5 ✓
00成立 → 跳过替换0 ✓
易错：这里要用 jle（−x≤0 ⇔ x≥0 时跳过），不是 jge。写完务必把 正数 / 负数 / 0 三种情况各代一遍——考场口算两分钟，能稳拿这道题。

练习题 4.6 条件传送版 absSum

修改 sum 函数的 Y86-64 代码（图 4-6），实现函数 absSum，它计算一个数组的绝对值的和。在内循环中使用条件传送指令。

参考解答与讲解

只改 loop 体的判断：把"条件跳转＋rrmovq"压成一条 cmovg（条件传送指令本身见上方 B0 卡）。注意条件反过来了——cmov 是"满足才替换"，所以要用"x＜0"即"−x＞0"的 g：

loop:
    mrmovq (%rdi),%r10   # r10 = *start
    xorq %r11,%r11       # r11 = 0
    subq %r10,%r11       # r11 = 0−x = −x，设置 CC
    cmovg %r11,%r10      # 仅当 −x > 0（即 x < 0）时 r10 = −x
    addq %r10,%rax       # sum += |x|
    addq %r8,%rdi        # start++
    subq %r9,%rsi        # count--
xcmovg 的条件（−x＞0）r10 最终
5−5＞0 假 → 不替换5 ✓
−55＞0 真 → 替换5 ✓
00＞0 假 → 不替换0 ✓
为什么教材成对出这两题：cmov 无分支，没有分支预测错误的惩罚（呼应第 3 章"条件传送编译优化"）。跳转版多一条指令但路径直观；传送版恒定 4 条，流水线更友好。考试要点：条件跳转看"保持不变的情况"，条件传送看"需要替换的情况"——两者条件正好互补。

C · HCL 与组合电路 4.2 节 · 练习题 4.9 / 4.10 / 4.11

HCL（硬件控制语言）用类 C 的表达式描述组合电路的连线。先掌握三个位级积木，再上字级。

C1 · 组合电路与 HCL 的基本约定

  • 组合电路：输出恒等于输入的某布尔函数——不存储任何状态、输出只随输入变、不允许反馈环。
  • HCL 使用与 C 相同的逻辑运算符 && || ! ==，但含义是" wires 的连接"，没有短路求值、没有先后顺序。
  • 字级信号用中等粗度线表示；位级布尔信号用细线/虚线（图 4-12 的画法约定）。

背景与练习题 4.9 位级：eq 与 xor

正文中定义的位相等信号（图 4-10　检测位相等的组合电路：当输入都为 0 或都为 1 时，输出等于 1）：

bool eq = (a && b) || (!a && !b);

练习题 4.9　写出信号 xor 的 HCL 表达式，xor 就是异或，输入为 a 和 b。信号 xor 和上面定义的 eq 有什么关系？

参考解答
bool xor = (!a && b) || (a && !b);

关系：xor 是 eq 的补（相反）——两位"不同"当且仅当"不相等"，所以 xor = !eq（或 eq = !xor）。这个结论正是 4.10 用异或搭相等电路的出发点。

C3 · 多路复用器与 HCL case 表达式

位级 MUX（图 4-11：s 为 1 输出 a，为 0 输出 b）：

bool out = (s && a) || (!s && b);

字级选择用 case 表达式：方括号包裹若干"选择表达式 : 值;"，从上到下第一个成立者胜出，最后的 1 : … 是默认分支。计算三个字 A、B、C 最小值的正文示例（练习题 4.11 所指代码，共 4 个 X<=Y 比较）：

word Min3 = [
    A <= B && A <= C : A;    # 2 个比较：A<=B、A<=C
    B <= A && B <= C : B;    # 2 个比较：B<=A、B<=C
    1                : C;    # 否则选 C
];

练习题 4.10 64 位字级相等电路

假设你用练习题 4.9 中的异或电路而不是位级的相等电路来实现一个字级的相等电路。设计一个 64 位字的相等电路需要 64 个位级的异或电路，另外还要两个逻辑门。

参考解答与讲解

推理链：两位相等 ⇔ 异或结果为 0（4.9 的结论 xor = !eq）。于是 64 位相等 ⇔ 64 个异或结果全为 0 ⇔ 它们的或为 0：

  1. 64 个位级异或电路：xi = Ai ⊕ Bi（i = 0…63）；

练习题 4.11 Min3 只用三次比较

计算三个字中最小值的 HCL 代码包含了 4 个形如 X<=Y 的比较表达式。重写代码计算同样的结果，但只使用三个比较。

参考解答与讲解

观察：原代码第二行 B<=A && B<=C 的意思是"走到这里说明 A 不是最小，再确认 B 是不是最小"。但此时其实只需要比较 B 和 C——因为 A 已经出局，最小值只可能在 B、C 之中：

word Min3 = [
    A <= B && A <= C : A;    # 2 个比较：A 是最小
    B <= C           : B;    # 1 个比较：A 出局后，min 只能在 B、C 中
    1                : C;
];

为什么正确：进入第二行时必有"A>B 或 A>C"。
· 若 A>B：B＜A 且 B≤C → B 是最小，选 B ✓；
· 若 A≤B 且 A>C：则 C＜A≤B → B≤C 不成立，落到默认分支选 C ✓。

方法论：case 表达式自上而下短路，后面分支可以免费利用前面分支隐含的信息——这就是省掉一次比较的来源。同类题（如 4.12 求中间值）都适用。
