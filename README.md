## 四、怎么用这套笔记（建议学习路径）

1. **第一遍（主线）**：按短系列 58P 顺序看课，对照 `docs/01~10` 逐章笔记。短系列节奏快，一集一个知识点，记公式/结论最合适。
2. **第二遍（攻坚）**：第 4 章流水线、第 7 章链接、第 9 章虚拟内存、第 6 章缓存 是公认难点，回看直播版对应 P（P12-P17、P24-P28、P34-P40、P21-P23）。
3. **刷题前**：过一遍 [`知识点专项梳理.md`](docs/知识点专项梳理.md)，把跨章节的题感建立起来。
4. **考前**：只翻 [`公式速查.md`](docs/公式速查.md) + [`概念速查.md`](docs/概念速查.md) 两页。
5. **配合 Lab**：Data Lab（第 2 章）、Bomb Lab（第 3 章）、Cache Lab（第 6 章）、Shell Lab（第 8 章）、Malloc Lab（第 9 章）能极大加深理解。

> **考研 408 提示**：该 UP 主另有《408-操作系统》《408-计算机网络》《408-计算机组成原理》《408-数据结构》长课，CSAPP 第 3/6/9 章与 408 的计算机组成原理、操作系统部分高度重合，可配套复习。

## 五、记号约定

本笔记面向 **GitHub Markdown** 编写，数学公式使用 **LaTeX 数学语法**（GitHub 内置 MathJax 渲染）。

> ⚠️ **重要：行内公式必须用 `` $`...`$ `` 形式**（美元符号 + 反引号包裹），这是 GitHub 官方推荐且唯一稳定的行内写法。
> 直接写单个 `$` 的 `` $x_{w-1}$ `` 在 GitHub 上**不会渲染**，且其中的下划线会被 Markdown 当成斜体标记吞掉，显示成乱码。原因见文末说明。

- **行内公式**：`` $`2^w`$ ``、`` $`x_{w-1}`$ ``、`` $`-2^{w-1}`$ ``
- **块级公式**：`$$` 独占一行，公式独立成段（块级公式用普通 `$$` 即可，无需反引号）
- **多字符上/下标必须加花括号**：`` $`2^{w-1}`$ ``（而非 `` $`2^w-1`$ ``，后者会渲染成「2的w次方再减1」）
- 代码、汇编、文件路径、十六进制值、ASCII 图示仍用行内代码或代码块，**不**做公式化

> 💡 **为什么是 `` $`...`$ ``**：GitHub 的 Markdown 解析器先处理斜体（`_..._`），再识别公式。像 `` $`\mathrm{B2U}_w(x) = \sum_{i=0}^{w-1}`$ `` 这类含多个下划线的公式，`_` 会被优先配对成 `<em>` 斜体标记，导致公式识别失败。用反引号把公式包住，可以让它跳过 Markdown 的文本解析，公式原样交给 MathJax。此外 `$` 直接紧贴中文字符也会导致不渲染，`` $`...`$ `` 同样能规避。
>
> 📖 参考：GitHub 官方文档 [Writing mathematical expressions](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)

**查看方式**：在 GitHub 网页上直接打开 `.md` 文件即可看到渲染效果；用本地编辑器（VS Code / 记事本）打开会看到 LaTeX 源码，属正常现象。本地预览推荐 VS Code 加装 **Markdown Preview Enhanced** 扩展。

**符号含义**

| 记号 | 含义 |
|---|---|
| $`w`$ | 字长（位数） |
| $`2^w`$ | 2 的 $`w`$ 次方 |
| $`x_{w-1}`$ | 二进制位向量的最高位（符号位） |
| $`\bmod`$、$`/`$ | 分别表示取模与整除（向零舍入） |
| ⚠️ / 💡 / 📌 | 分别标注高频考点 / 理解技巧 / 易错点 |
