# 第 9 章 虚拟内存

> 对应课程：短系列 9-1、9.2 录播课｜直播版 P34 ~ P40（覆盖 9.1~9.7，最全，含 malloclab）
> 本章是 CSAPP 的**顶峰**：虚拟内存把"缓存思想"用到地址空间，涉及页表、TLB、地址翻译、mmap、动态内存分配器。考研操作系统与 CSAPP 的重合区。

---

## 9.1 虚拟内存（VM）概述 ⚠️

### 9.1.1 物理寻址 vs 虚拟寻址

| 方式 | 说明 |
|---|---|
| **物理寻址** | CPU 直接发物理地址给主存（早期/嵌入式） |
| **虚拟寻址** | CPU 发**虚拟地址（VA）**，由**MMU**（内存管理单元）翻译成物理地址（PA） |

### 9.1.2 VM 的三大作用 ⚠️⚠️

**① 用 DRAM 作为磁盘的高速缓存**
- 虚拟内存把磁盘当作下层的"主存"，主存是它上面的缓存
- 单位是**页（page）**，通常 4KB 或 2MB/1GB（大页）
- **页缺失（page fault）** = 缓存缺失，从磁盘调入（需要换页时）

**② 提供每个进程独立的、一致的地址空间（内存管理）**
- 简化链接（每个程序认为从同一地址开始）
- 简化加载（只需映射页，无需全量载入）
- 简化共享（多个进程可共享同一物理页）
- 简化内存分配（`malloc` 通过 `mmap` 请求新页）

**③ 保护内存**
- 每个页表项（PTE）有权限位：读/写/执行/用户/内核
- 阻止非法访问，防止进程互相干扰

## 9.2 页表与地址翻译 ⚠️⚠️⚠️

### 9.2.1 页表（Page Table）

- **页表**：虚拟页号 → 物理页号/磁盘地址 的映射表，存放在**物理内存**中
- 每页一个**页表项（PTE）**：$\text{有效位} \mid \text{物理页号(PPN)} \mid \text{权限位}$
  - 有效位 = 1：在内存中，PPN 有效
  - 有效位 = 0：缺页（或在磁盘上）

```
┌───────┬─────────────┬────┬────┐
│ 有效位 │  物理页号PPN  │RW │ 权限…│
└───────┴─────────────┴────┴────┘
```

### 9.2.2 地址翻译流程

**虚拟地址（VA）划分**：
$$
VA = [\text{虚拟页号}\ \mathrm{VPN}\ (n-p\ \text{位}) \mid \text{页偏移}\ \mathrm{VPO}\ (p\ \text{位})] \\
PA = [\text{物理页号}\ \mathrm{PPN} \mid \text{物理页偏移}\ \mathrm{PPO}]
$$

其中 $PPO = VPO$（页内偏移一致），$PPN = \text{页表}[\mathrm{VPN}]$。

**命中时的翻译**：
$$
VA \to \text{提取}\ \mathrm{VPN} \to \text{页表基址}[\mathrm{VPN}] \to \mathrm{PTE} \to \text{提取}\ \mathrm{PPN} \to PA = \mathrm{PPN} \Vert \mathrm{VPO}
$$

**缺失时的处理（缺页异常）**：
1. 触发**缺页故障（fault）** → 陷入内核
2. 内核从磁盘读到物理页，更新 PTE（有效位=1）
3. **重新执行**引发缺失的指令（⚠️ 故障会重试，这正是第 8 章"故障"的例子）

### 9.2.3 页表项的访问流程（结合缓存/TLB）

```
CPU 发 VA
 → 查 TLB（页表的缓存，存最近用到的 PTE）
   → TLB 命中：直接得 PPN
   → TLB 缺失：访问主存中的页表 → 读 PTE → 装入 TLB
 → 查页表得到 PPN → 合成 PA
 → 用 PA 访问主存/缓存
```

⚠️ **两级缓存思想**：**TLB 缓存"页表"**，**主存缓存"磁盘页"**。

---

## 9.3 TLB（Translation Lookaside Buffer）⚠️

- **TLB**：页表的**缓存**，存最近访问的 PTE
- 与普通缓存一样有：命中/缺失、组相联、LRU

**TLB 索引**（通常用 VPN 的低位做组索引）：
$$
VPN = [\mathrm{tag} \mid \mathrm{TLB}\ \text{索引}]
$$

**命中组合（⚠️ 考研/面试常考"多级命中"）**

| 场景 | TLB | 页表 | 缓存/主存 |
|---|---|---|---|
| 全命中 | ✅ | — | ✅（缓存命中） |
| TLB 命中、缓存缺失 | ✅ | — | 从主存取块 |
| TLB 缺失、页表命中 | ❌ | ✅（页在内存） | 从主存读 PTE |
| 缺页 | ❌ | ❌ | 从磁盘取页 |

## 9.4 多级页表 ⚠️⚠️

**问题**：一级页表太大（64 位地址空间 + 4KB 页 → 需要天文数字级条目）。

**多级页表（分层级页表）**：把页表本身再分页，按需分配，大幅节省内存。

$$
VA = [\mathrm{VPN_1} \mid \mathrm{VPN_2} \mid \dots \mid \mathrm{VPN_k} \mid \mathrm{VPO}]
$$

逐级索引各自的子页表

- **Intel Core i7 用 4 级页表**（PML4 → PDP → PD → PT）
- 顶级页表常驻内存，低级别页表**按需分配**（很多地址空间从不使用）
- 一个 VPO 固定的地址 → 逐级找到 PTE

**i7 页表项（4KB 页）**：共 64 位，含 NX（不可执行）、P（有效）、RW、US、A（访问位，供替换）、D（脏位，写回）等。

---

## 9.5 Intel Core i7 地址翻译实例 ⚠️

- 48 位虚拟地址
- 4KB 页时：$VPO = 12\ \text{位}$，$VPN = 36\ \text{位}$，分成 4 级（$9\ \text{位} \times 4$）
- 2MB 大页：$VPO = 21\ \text{位}$
- **注意**：i7 的页表项里同时有 A/D 位，配合 TLB

**缓存索引**：i7 的 L1/L2/L3 用**物理地址**索引（物理地址 tag/index/offset），所以要先完成地址翻译才能访问缓存——因此 **TLB 在缓存之前起作用**。

## 9.6 内存映射（mmap）⚠️

**内存映射（Memory Mapping）**：把磁盘对象映射到虚拟内存空间。
- 每个进程中，VM 空间被划分为若干**映射区**
- 两个来源：**普通文件** 和 **匿名文件**（全零页，如 `calloc`/堆）

**共享对象 vs 私有对象（写时复制）** ⚠️
| 类型 | 行为 |
|---|---|
| **共享对象**（MAP_SHARED） | 多个进程共享同一物理页，写对所有人可见（用于共享内存/IPC） |
| **私有对象**（MAP_PRIVATE） | 使用**写时复制（COW）**：首次只读共享，写入时才复制私有一份 |

### 9.6.1 fork 中的内存映射

- `fork` 为子进程创建**私有**映射（COW）→ 父子的只读页共享，写时复制

### 9.6.2 execve 中的内存映射

- 清空之前的用户态虚拟内存，加载新程序：代码段/数据段映射到文件，`.bss` 和栈映射到匿名文件
- **用户栈**：从高地址向下增长

### 9.6.3 mmap 系统调用

```c
void *mmap(void *start, size_t length, int prot, int flags, int fd, off_t offset);
```
- 也可用于文件 I/O（替代 read/write）

## 9.7 动态内存分配器 ⚠️⚠️

**目的**：在运行时按需分配/释放堆内存。

**堆（Heap）**：位于虚拟地址空间的数据段之上，向上增长，由 `brk`/`mmap` 扩展。

**分配器类型**
| 类型 | 函数 | 说明 |
|---|---|---|
| **显式分配器** | `malloc` / `free` | 程序员手动释放 |
| **隐式分配器** | `new` / GC | 自动回收（垃圾回收） |

**为什么动态分配器慢**：堆没有硬件缓存语义，且要维护空闲块结构。

### 9.7.1 碎片（Fragmentation）⚠️

| 类型 | 定义 |
|---|---|
| **内部碎片** | 已分配块内未使用的空间（如对齐填充、块头） |
| **外部碎片** | 空闲块总空间够，但被分割成许多不连续小块，无法满足请求 |

### 9.7.2 请求、释放与合并

- **合并（Coalescing）**：释放时把相邻空闲块合并成一个大块
  - **立即合并**：每次 free 都合并；**延迟合并**：等到无法分配时再合并
- 需区分块是**空闲**还是**已分配** → 用**标记（Boundary Tag）**：块头部和尾部都存大小+分配位

### 9.7.3 放置策略（Placement Policy）

| 策略 | 做法 | 特点 |
|---|---|---|
| **首次适配（First-fit）** | 找第一个够大的空闲块 | 简单，可能产生小的剩余块 |
| **下次适配（Next-fit）** | 从上次位置继续找 | 减少扫描 |
| **最佳适配（Best-fit）** | 找大小最接近的 | 空间利用率高，慢 |

### 9.7.4 空闲链表组织

| 方式 | 说明 |
|---|---|
| **隐式空闲链表** | 通过头/尾标记遍历所有块，无需显式指针 |
| **显式空闲链表（Explicit）** | 空闲块内用指针串联，加快查找 |
| **分离空闲链表（Segregated）** | 按大小分类成多个链表，分配快、碎片少 |

### 9.7.5 块的结构（带边界标签）

```
┌─────────┬──────────────┬─────────┐
│ 头部     │ 有效载荷       │ 尾部(可选)│
│ 大小|分配位│              │ 大小|分配位│
```
- 头部 8 字节（大小+1 位分配标志）→ 有效载荷对齐到 8/16 字节
- 尾部用于 O(1) 合并（能快速看前一个块是否空闲）
- **节省技巧**：空闲块内可以用前 8 字节放下一/前一空闲块指针，把"头/尾"合并存放

## 9.8 垃圾回收与常见错误 ⚠️

### 9.8.1 隐式分配器（垃圾回收）

- **Mark & Sweep（标记-清除）**：
  1. **标记（Mark）**：从根（全局变量、栈）出发，遍历可达对象并标记
  2. **清除（Sweep）**：扫描堆，回收所有未标记（不可达）对象
- **引用计数**：每个对象计引用数，为 0 时回收（需处理循环引用）

### 9.8.2 常见内存错误（⚠️ 考研常考判断/纠错）

| 错误 | 例子/说明 |
|---|---|
| 间接引用坏指针 | `scanf("%d", val)` 忘了 `&` |
| 读未初始化内存 | 忘赋值 |
| 越界/栈缓冲区溢出 | 读/写数组越界 |
| 覆盖内存 | 字符串放不下 (`strcpy` 越界) |
| 引用不存在的变量 | 返回局部变量的指针 |
| 引用已释放内存 | 使用 `free` 后的指针 |
| `free` 多次 | 重复释放 |
| 内存泄漏 | 分配后不再释放 |
| `malloc` 忘检查失败 | 忽略 NULL 返回 |

## 本章速记

- **VM 三大作用**：缓存磁盘 + 内存管理 + 内存保护
- **$VA = [\mathrm{VPN} \mid \mathrm{VPO}]$**，**$PA = [\mathrm{PPN} \mid \mathrm{PPO}]$**，$PPN = \text{页表}[\mathrm{VPN}]$，$PPO = VPO$
- **缺页是"故障"**，处理完**重试原指令**
- **TLB 缓存页表**；多级页表省内存；i7 用 **4 级**
- **写时复制（COW）**：私有对象、`fork`、`execve` 的关键
- 分配器：**显式 vs 隐式**；**内部/外部碎片**；**首次/最佳适配**；**合并**
- 垃圾回收：**标记-清除 / 引用计数**
- 常见错误：野指针、越界、重复释放、**内存泄漏**
