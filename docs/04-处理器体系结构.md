# 第 4 章 处理器体系结构

> 对应课程：短系列 4-1 ~ 4-10（10P）｜直播版 P12 ~ P17（含 Verilog HDL）
> 本章用 **Y86-64** 这个简化指令集，自底向上搭出一个处理器：先顺序（SEQ），再流水线。**考研组成原理与 CSAPP 的重合区**。

---

## 4.1 指令集体系结构（ISA）

**ISA 是软硬件接口**：定义了程序员可见的状态 + 指令的语义。

**Y86-64 的程序员可见状态**
- 15 个通用寄存器：`%rax, %rcx, %rdx, %rbx, %rsp, %rbp, %rsi, %rdi, %r8~%r14`
- 条件码：`ZF, SF, OF`
- PC（程序计数器）
- 内存（字节数组）
- 状态码 `Stat`：`AOK / HLT / ADR / INS`

**Y86-64 指令集**

| 指令 | 说明 |
|---|---|
| `halt` | 停止 |
| `nop` | 空操作 |
| `rrmovq rA, rB` | 寄存器传送 |
| `irmovq V, rB` | 立即数→寄存器 |
| `rmmovq rA, D(rB)` | 寄存器→内存 |
| `mrmovq D(rB), rA` | 内存→寄存器 |
| `OPq rA, rB`（add/sub/and/xor） | 算术逻辑 |
| `jXX Dest` | 跳转（jmp/jle/jl/je/jne/jge/jg） |
| `cmovXX rA, rB` | 条件传送 |
| `call Dest` / `ret` | 调用/返回 |
| `pushq rA` / `popq rA` | 压栈/出栈 |

⚠️ **与 x86-64 的差异**：Y86-64 指令定长（多为 10 字节）、不支持比例变址、`mrmovq/mrmovq` 显式区分访存方向。

---

## 4.2 数字电路与 HCL

### 4.2.1 组合逻辑 vs 时序逻辑

| 类型 | 特点 | 例子 |
|---|---|---|
| **组合逻辑** | 输出只取决于当前输入，无记忆 | ALU、多路选择器、加法器 |
| **时序逻辑** | 输出依赖当前输入 + **历史状态**，由时钟驱动 | 寄存器、寄存器文件、内存 |

**时钟**：边沿触发，寄存器在时钟上升沿更新，保证状态稳定。

⚠️ **硬件设计中一个时刻只能写一个寄存器**；多路选择器（MUX）用于在多个来源间选择。

### 4.2.2 HCL（硬件控制语言）

用布尔表达式描述组合逻辑：
```
bool eq = (a == b);
word out = [
    s : A;
    1 : B;
];
```
- `bool` 表达式对应逻辑门
- `word` 表达式对应 MUX/ALU 的控制

---

## 4.3 Y86-64 的顺序实现（SEQ）⚠️

**SEQ = 每个时钟周期执行完一条完整指令**。

### 4.3.1 六个阶段

| 阶段 | 英文 | 做什么 |
|---|---|---|
| 1. **取指** | Fetch | 从 PC 读指令字节 icode/ifun/rA/rB/valC，计算 $valP = PC + \text{指令长度}$ |
| 2. **译码** | Decode | 读寄存器 $valA = R[rA]$，$valB = R[rB]$ |
| 3. **执行** | Execute | ALU 计算 $valE$（算术结果/地址/$valP$ for jmp） |
| 4. **访存** | Memory | 读写内存，得 $valM$ |
| 5. **写回** | Write back | 写寄存器文件 |
| 6. **更新 PC** | PC update | $PC \leftarrow valP$ 或跳转目标 |

⚠️ **各指令的阶段差异**（高频考点）
- `rrmovq`：无访存、无 $valM$
- `irmovq`：无译码（$valA$/$valB$ 不用）
- `mrmovq`：$valE$ 作为地址，访存得 $valM$
- `cmovXX`：根据条件码决定是否写回
- `call`：$valE = -8 + valP$，压栈返回地址，$PC = valC$
- `ret`：从栈弹出地址送到 PC

### 4.3.2 SEQ 硬件结构

- **PC** 寄存器
- **指令内存**（只读，组合读）
- **寄存器文件**（两个读端口 A/B，一个写端口）
- **ALU**（执行阶段）
- **数据内存**（读/写）
- **条件码寄存器**
- **控制逻辑**（根据 icode/ifun 生成各阶段控制信号）

📌 **SEQ 的性能**：时钟周期必须容纳最慢指令（含访存）→ 效率低。这是引入流水线的动机。

---

## 4.4 流水线的通用原理 ⚠️⚠️

### 4.4.1 关键指标

| 指标 | 定义 |
|---|---|
| **吞吐量（Throughput）** | 单位时间完成的任务数 |
| **延迟（Latency）** | 单个任务从开始到完成的耗时 |

**理想流水线**（$k$ 级，每级延迟 $t$）：
- 非流水：延迟 $k \cdot t$，吞吐 $1/(k \cdot t)$
- 流水：延迟 $k \cdot t$（不变），吞吐 $1/t$ → **加速比 $\approx k$**

💡 流水线**不减少单条指令延迟，只提高吞吐量**。

### 4.4.2 流水线寄存器

在每级之间插入寄存器，保存该级产生的结果传给下一级：
```
F → [寄存器] → D → [寄存器] → E → [寄存器] → M → [寄存器] → W
```
每条指令在每个阶段占用一个时钟周期，多条指令重叠执行。

### 4.4.3 流水线的局限性

- **不一致的划分**：各级延迟不同，时钟周期取决于最慢一级。
- **流水线过深**：寄存器开销占比变大，收益递减。
- **冒险（Hazard）**：下一条指令无法在预定周期执行 —— 本章重点。

---

## 4.5 数据冒险（Data Hazard）⚠️⚠️

### 4.5.1 三类冒险

| 类型 | 原因 | 例子 |
|---|---|---|
| **数据冒险** | 指令依赖前面指令的结果 | `addq %rax,%rbx` 后 `mrmovq (%rbx),%rcx` |
| **控制冒险** | 分支/跳转改变 PC | `jne` 后不知道下条指令 |
| **结构冒险** | 硬件资源冲突 | 两条指令同时要访存 |

### 4.5.2 数据冒险的解决

**① 停顿（Stalling）**：插入气泡（bubble），简单但慢。

**② 转发/旁路（Forwarding/Bypassing）** ⚠️ 核心
- 不等结果写回寄存器文件，直接**从流水线寄存器前递**给需要的阶段。
- 来源：`valE`（执行结果）、`valM`（访存结果）。
- 例：`addq %rax,%rbx`（E 阶段算出）→ 下一条 `mrmovq (%rbx)` 需在 E 阶段用，可前递。

**③ load/use 冒险（Load-Use Hazard）** ⚠️
```asm
mrmovq (%rax), %rbx   # M 阶段才得到 valM
addq %rbx, %rcx       # 紧接着就要用
```
- 数据要等 M 阶段结束，转发也来不及 → **必须停顿 1 个周期**（插入气泡）。
- 检测条件：`E_icode == mrmovq && (D_srcA ∈ {E_dstM} || D_srcB ∈ {E_dstM})`。
- 汇编器可自动插入 `nop` 避免，但更好的做法是**调整指令顺序**（第 5 章）。

### 4.5.3 转发优先级

一个寄存器可能有多个来源（E/M/W），**优先级：E > M > W**（越"新"的结果越优先），由 HCL 的选择逻辑实现。

---

## 4.6 控制冒险（Control Hazard）⚠️⚠️

分支指令在**执行阶段（E）** 才能确定是否跳转，但取指（F）已经取了后面的指令。

### 4.6.1 解决策略

| 策略 | 做法 | 代价 |
|---|---|---|
| **停顿** | 分支后暂停取指，等确定 | 浪费 3 个周期 |
| **分支预测（预测跳转）** | 猜跳转，取目标处指令 | 猜错要取消 |
| **分支预测（预测不跳转）** | 猜不跳，继续顺序取指 | 猜错要取消 |
| **延迟槽** | 分支后固定插一条指令 | 编译器调度 |
| **投机执行** | 提前执行并保留，确认后提交 | 复杂 |

### 4.6.2 分支预测错误（Misprediction）

- **取消（Canceling）**：把错误取入的指令替换为气泡，清除控制信号。
- 实现：在 E 阶段检测到应该跳转/不该跳转与实际不符时，往 D 阶段注入 `bubble`。

⚠️ **与异常的区别**：预测错误是**内部**的，不改变程序员可见状态；流水线异常（如非法指令、缺页）必须让**之前的所有指令完成、之后的指令不产生副作用**。

### 4.6.3 流水线中的异常处理

- 只有 **E/M/W 阶段**的指令可能引发异常
- 要让异常看起来"精确"（precise）：异常指令之前的所有指令都完成，之后的不提交
- Y86-64 用 `Stat` 字段传递状态码

---

## 4.7 Y86-64 流水线实现

### 4.7.1 五级流水

```
F(取指) → D(译码) → E(执行) → M(访存) → W(写回)
```
用五个流水线寄存器：`F_predPC`、`D_*`、`E_*`、`M_*`、`W_*`。

### 4.7.2 控制逻辑（HCL 核心）

- **选择 valA/valB 的来源**（寄存器文件 or 转发）
- **产生 dstE/dstM/srcA/srcB**（用于冒险检测）
- **流水线控制**：`F_stall, D_stall, D_bubble, E_bubble, M_bubble, W_stall`
  - **load/use 冒险** → 停顿 F、D，注入 bubble 到 E
  - **分支预测错误** → 注入 bubble 到 D/E
  - **ret 指令** → 停顿 F（因为返回地址在 M 阶段才知道）

📌 `ret` 的处理：可以改为"预测返回地址"，或在取指阶段停顿 3 周期。

---

## 本章速记

- **ISA**：软硬件接口，Y86-64 是简化模型
- **SEQ 六阶段**：取指 → 译码 → 执行 → 访存 → 写回 → 更新 PC
- **流水线**：提高吞吐量（$\approx k$ 倍），不降延迟
- **数据冒险**：转发（E > M > W）为主，**load/use 必须停顿 1 周期**
- **控制冒险**：分支预测 + 预测错误取消（bubble）
- 异常要**精确**：之前完成、之后不生效
