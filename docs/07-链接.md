# 第 7 章 链接

> 对应课程：短系列 7-1 ~ 7-8（8P）｜直播版 P24 ~ P28
> 本章讲**程序从 .o 到可执行文件的最后一步**：符号解析 + 重定位。是理解"未定义引用""重复定义""静态库顺序"等报错的钥匙。

---

## 7.1 编译器驱动程序

**完整编译流程**（以 `gcc -o prog main.c sum.c` 为例）：
```
main.c ─cc1→ main.s ─as→ main.o ─┐
                                  ├─ld→ prog（可执行文件）
sum.c  ─cc1→ sum.s  ─as→ sum.o  ─┘
```
- `cpp` 预处理 → `cc1` 编译 → `as` 汇编 → `ld` 链接
- **链接器（ld）**：合并目标文件，解析符号，重定位。

💡 用 `-c` 只编译不链接，用 `-S` 生成汇编，`-E` 只预处理，便于观察各阶段。

---

## 7.2 可重定位目标文件（.o）与 ELF 格式 ⚠️

**ELF（Executable and Linkable Format）** 是 Linux 上的目标文件格式。

### 7.2.1 ELF 结构

```
┌─────────────────┐
│   ELF 头         │  ← 魔数、类型、机器、节头部表偏移…
├─────────────────┤
│   .text         │  已编译程序的机器代码
│   .rodata       │  只读数据（如格式串、跳转表）
│   .data         │  已初始化的全局/静态变量
│   .bss          │  未初始化（或被初始化为0）的全局/静态变量，仅占位不占空间
│   .symtab       │  符号表：函数和全局变量信息
│   .rel.text     │  .text 的重定位条目
│   .rel.data     │  .data 的重定位条目
│   .debug        │  调试信息
│   .line         │  行号映射
│   .strtab       │  字符串表（符号名）
├─────────────────┤
│  节头部表        │
└─────────────────┘
```

⚠️ **重点区分**（高频）
| 节 | 内容 | 特点 |
|---|---|---|
| `.text` | 机器代码 | |
| `.rodata` | 只读数据 | 如 `printf` 的格式串、`switch` 跳转表 |
| `.data` | **已初始化**的全局/静态变量 | 占用文件空间 |
| `.bss` | **未初始化**的全局/静态变量 | **不占文件空间**，运行时清零 |
| `.symtab` | 符号表 | |
| `.rel.text` / `.rel.data` | 重定位信息 | 已重定位的可执行文件不再需要 |

📌 **`.bss` 的意义**：不占磁盘空间，只需记录大小，运行时分配并清零。

### 7.2.2 其他目标文件类型

| 类型 | 说明 |
|---|---|
| **可重定位目标文件（.o）** | 可与其他 .o 合并 |
| **可执行目标文件（a.out）** | 可直接加载运行 |
| **共享目标文件（.so）** | 可在加载/运行时动态链接 |

## 7.3 符号和符号表

**符号（Symbol）** = 一个可被链接的目标（函数名、变量名）。

| 类别 | 说明 |
|---|---|
| **全局符号（Global）** | 定义在本模块、可被其他模块引用的**非静态**函数/全局变量 |
| **外部符号（External）** | 本模块引用但定义在别处的符号 |
| **局部符号（Local）** | 带 `static` 属性的函数/变量，**只在定义模块内可见** |

📌 **局部符号 $\ne$ 局部变量**：局部（自动）变量在栈上，不在符号表里；只有 `static` 局部变量才进符号表。

**符号表条目（Elf64_Symbol）**：
| 字段 | 说明 |
|---|---|
| `name` | 字符串表偏移 |
| `value` | 符号地址（重定位文件中是节内偏移） |
| `size` | 目标大小 |
| `type` | `FUNC` / `OBJECT` / `SECTION` |
| `binding` | `GLOBAL` / `LOCAL` / `WEAK` |
| `section` | 所属节（`COMMON` / `ABS` / 节索引） |

**三个伪节**：`ABS`（不该重定位）、`UNDEF`（未定义，引用他处）、`COMMON`（未初始化的弱全局符号）。

---

## 7.4 符号解析与静态库 ⚠️⚠️

### 7.4.1 链接器的工作

1. **符号解析（Symbol Resolution）**：把每个符号引用关联到唯一的符号定义
2. **重定位（Relocation）**：把各节合并，确定运行时地址，修改所有引用

### 7.4.2 强符号 vs 弱符号 ⚠️

| 类型 | 定义 |
|---|---|
| **强符号（Strong）** | 函数、已初始化的全局变量 |
| **弱符号（Weak）** | 未初始化的全局变量、带 `static` 的 |

**解析规则（高频）**
1. 不允许有**两个同名强符号** → 链接错误"multiple definition"
2. 一个强符号 + 一个弱符号 → 选**强符号**
3. 两个弱符号 → 任选一个（实现相关），**危险**

📌 **常见坑**：两个模块都定义了 `int x;`（未初始化，弱符号）→ 链接器合并成一个，若其中一个还初始化了值就出错。**解决：定义时加 `static` 或 `extern`，或初始化。**

### 7.4.3 静态库（.a）

- **静态库** = 一组 .o 的**归档文件（archive）**，用 `ar` 创建
- 链接时**只复制被用到的 .o**，减小可执行文件
- ⚠️ **解析顺序（关键）**：链接器**从左到右**扫描命令行，维护符号集 `E`（已合并）、`U`（未解析）、`D`（已定义）
  - 遇到 .o：加入 E，更新 U/D
  - 遇到 .a：只取**能解决当前 U 中符号**的成员
  - **若 .a 在引用它的 .o 之前，则不会被解析** → 报 undefined reference

💡 **解决库顺序问题**：把 `.a` 放在引用它的 `.o` 之后；或用 `--start-group lib1.a lib2.a --end-group` 循环扫描；或 `-Wl,--whole-archive`。

## 7.5 重定位（Relocation）⚠️

### 7.5.1 两个步骤

1. **合并节、分配地址**：把所有同类型节合并（如所有 `.text` 合成一个大 `.text`），并分配运行时地址
2. **重定位符号引用**：修改每条引用，使其指向正确的运行时地址

### 7.5.2 重定位条目

存放在 `.rel.text` / `.rel.data` 中，每个条目描述一处需要修改的引用：

| 字段 | 说明 |
|---|---|
| `offset` | 需要修改的位置（相对节的偏移） |
| `type` | 重定位类型 |
| `symbol` | 引用的符号 |
| `addend` | 偏移量 |

**x86-64 两种基本重定位类型**（⚠️）
| 类型 | 用途 | 算法 |
|---|---|---|
| **R_X86_64_PC32** | PC 相对引用（如函数调用） | $*refptr = \mathrm{ADDR}(\text{symbol}) + \text{addend} - \mathrm{ADDR}(\text{refptr的位置})$ |
| **R_X86_64_32** | 绝对寻址 | $*refptr = \mathrm{ADDR}(\text{symbol}) + \text{addend}$ |

💡 **PC 相对寻址的好处**：指令不依赖加载地址，天然支持位置无关代码（PIC）。

---

## 7.6 可执行目标文件

- ELF 头中的 `e_entry` 指向**程序入口**（`_start`）
- **程序头部表（Program Header Table）**：描述段（segment）如何映射到内存，供加载器使用
- 段通常合并：代码段（`.text`，只读可执行）、数据段（`.data`，可读写）
- 加载：`execve` 时内核把可执行文件映射到虚拟地址空间（第 9 章）

---

## 7.7 动态链接共享库 ⚠️

### 7.7.1 共享库（.so）

- **动态链接**：程序运行时才链接库，多个进程**共享同一份代码**
- 优点：节省内存和磁盘、更新库不需重编译程序、支持插件
- 加载方式：**加载时链接**（程序启动）、**运行时链接**（`dlopen`/`dlsym`）

### 7.7.2 位置无关代码（PIC）⚠️

- **问题**：共享库被加载到任意地址，不能写死绝对地址
- **解决**：编译为 **PIC（Position-Independent Code）**
  - 模块内调用/跳转：用 PC 相对寻址
  - 模块内数据引用：用 PC 相对寻址
  - 模块外调用/数据：用 **GOT 和 PLT**

### 7.7.3 GOT 与 PLT

| 机制 | 全称 | 作用 |
|---|---|---|
| **GOT** | Global Offset Table | 全局偏移表，存放外部符号的地址 |
| **PLT** | Procedure Linkage Table | 过程链接表，外部函数调用的跳板 |

**延迟绑定（Lazy Binding）**：
- 第一次调用外部函数时才通过动态链接器解析其地址，写入 GOT
- 好处：不调用就不解析，加快程序启动
- 实现：PLT 条目首次跳转到解析器，之后直接跳 GOT 中的已解析地址

### 7.7.4 库打桩（Interpositioning）

在运行时替换库函数（用于追踪、调试、安全）：
- **编译时打桩**：用 `#define`/宏替换
- **链接时打桩**：`--wrap` 或提供同名函数
- **运行时打桩**：`LD_PRELOAD` 环境变量

---

## 本章速记

- 链接两步：**符号解析 + 重定位**
- `.data` 已初始化占空间，`.bss` 未初始化**不占文件空间**
- **强符号 vs 弱符号**：两个强符号 → 报错；强+弱 → 取强
- 静态库**从左到右**扫描，`.a` 必须在引用它的 `.o` 之后
- 重定位类型：**PC32（相对）/ 32（绝对）**
- 动态链接用 **PIC + GOT + PLT + 延迟绑定**
- 库打桩：`LD_PRELOAD`（运行时）
