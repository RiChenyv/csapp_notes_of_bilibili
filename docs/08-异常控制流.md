# 第 8 章 异常控制流

> 对应课程：短系列 8-1 ~ 8-6（6P）｜直播版 P29 ~ P33（含 shell）
> 本章讲**控制流如何在"正常指令"之外跳转**：异常 → 进程 → 系统调用 → 信号。操作系统与体系结构的桥梁。

---

## 8.1 异常控制流（ECF）概述

**控制流**：处理器执行的指令序列，`PC` 的轨迹。

**ECF（Exceptional Control Flow）**：正常控制流之外的控制转移，发生在四个层次：

| 层次 | 例子 |
|---|---|
| **硬件层** | 异常、中断 |
| **操作系统层** | 上下文切换、系统调用 |
| **应用层** | `fork`/`execve`、信号、非本地跳转 |
| **并发** | 线程、进程协作 |

---

## 8.2 异常（Exception）⚠️

**异常**：处理器状态中的事件触发，控制流从应用程序转移到**异常处理程序**。

### 8.2.1 异常表与异常号

- 每个异常有唯一**异常号**（非负整数）
- **异常表**：基址寄存器 + 异常号索引 → 处理程序地址
- 系统启动时初始化

### 8.2.2 异常的四种类型 ⚠️⚠️（高频）

| 类别 | 原因 | 同步/异步 | 返回行为 | 例子 |
|---|---|---|---|---|
| **中断（Interrupt）** | 外部 I/O 设备信号 | **异步** | 返回下一条指令 | 定时器、键盘、网络 |
| **陷阱（Trap）** | 有意的，执行指令 | 同步 | 返回下一条指令 | **系统调用**、断点 |
| **故障（Fault）** | 可恢复的错误 | 同步 | 可能**重新执行**当前指令 | **缺页**、除零、段错误 |
| **终止（Abort）** | 不可恢复的错误 | 同步 | **不返回** | 硬件错误、DRAM 校验错 |

💡 **记忆**：
- 中断 = 别人的事（异步，外部）
- 陷阱 = 我故意叫的（系统调用）
- 故障 = 我错了但能救（缺页 → 换页后重试）
- 终止 = 没救了（直接杀死）

⚠️ **系统调用（System Call）**：应用程序通过 `syscall` 指令陷入内核，内核执行服务后返回。是**受控的内核入口**（对比：异常是意外）。

---

## 8.3 进程（Process）⚠️

### 8.3.1 进程的概念

**进程** = 一个执行中的程序实例，是操作系统对"正在运行的程序"的抽象。

**核心思想**：
- **逻辑控制流**：进程独占 CPU 的假象（通过上下文切换）
- **私有地址空间**：每个进程看到自己的虚拟地址空间（第 9 章）

### 8.3.2 并发流

- 多个进程的逻辑流在时间上**重叠** → 并发
- **并发（Concurrent）**：宏观同时；**并行（Parallel）**：真正同时（多核）

### 8.3.3 用户模式与内核模式

| 模式 | 权限 | 说明 |
|---|---|---|
| **用户模式** | 受限 | 不能执行特权指令、不能直接访问内核数据 |
| **内核模式** | 全部 | 可执行任何指令、访问任何内存 |

- 模式切换：通过**异常/中断/系统调用**从用户态进入内核态
- 控制寄存器中的模式位决定当前模式

### 8.3.4 上下文切换（Context Switch）⚠️

**上下文** = 内核重新启动被抢占进程所需的状态（寄存器、PC、栈、页表等）。

**切换过程**：
1. 保存当前进程上下文
2. 恢复下一个进程上下文
3. 控制权交给新进程

**触发时机**：时间片用完、系统调用阻塞、中断。

---

## 8.4 进程的创建：fork ⚠️⚠️

### 8.4.1 fork 的行为

```c
pid_t fork(void);
```
- **调用一次，返回两次**：父进程返回**子进程 PID**，子进程返回 **0**；失败返回 -1
- 子进程是父进程的**完整副本**（代码、数据、堆、栈、文件描述符）
- 父子进程**并发执行**，顺序不确定
- 现代实现用**写时复制（Copy-on-Write, COW）** 优化：只读共享，写时才复制

📌 **经典例题**：`fork()` 两次会创建 4 个进程（$2^2$）；判断总进程数 = $2^n$（$n$ 次 fork）。

```c
pid_t pid = fork();
if (pid == 0) printf("child\n");
else printf("parent\n");
```

### 8.4.2 进程图（Process Graph）

- 用有向图表示 fork 的父子关系
- 每个 `fork` 产生一个新的分支 → 可分析所有可能的输出组合

### 8.4.3 回收（Reaping）

- **僵尸进程（Zombie）**：子进程已终止，但父进程尚未回收 → 占用内核中的进程表项
- **孤儿进程（Orphan）**：父进程先终止 → 被 `init`（PID 1）收养
- 回收方式：父进程调用 `wait` / `waitpid`

---

## 8.5 函数 execve 与 waitpid ⚠️

### 8.5.1 execve

```c
int execve(const char *filename, char *const argv[], char *const envp[]);
```
- **加载并运行新程序，覆盖当前进程**：成功后**不返回**（除非出错）
- 保留：PID、打开的文件描述符、环境
- 用途：shell 执行命令（fork 出子进程后 execve）

**`main` 的参数**：`argv[0]` 是程序名，`argv[argc] = NULL`，`envp` 是环境变量数组。

### 8.5.2 waitpid

```c
pid_t waitpid(pid_t pid, int *status, int options);
```
- 等待子进程终止并**回收**，返回子进程 PID
- `pid`：`>0` 指定进程；`-1` 任意子进程
- `options`：`WNOHANG`（非阻塞）、`WUNTRACED`
- **`wait(&status)`** = `waitpid(-1, &status, 0)`
- 状态宏：`WIFEXITED`、`WEXITSTATUS`、`WIFSIGNALED`、`WTERMSIG`

### 8.5.3 简易 shell 的实现 ⚠️

```
while (1) {
    读入命令行
    if (内建命令) 直接执行;
    else {
        pid = fork();
        if (pid == 0) {           // 子进程
            execve(程序, argv, envp);  // 执行命令
        } else {                  // 父进程
            waitpid(pid, &status, 0);  // 等待回收
        }
    }
}
```
💡 这就是"fork + execve + waitpid"的经典组合。

## 8.6 信号（Signal）⚠️⚠️

### 8.6.1 概念

**信号** = 一种**软件形式的中断**，通知进程发生了某种事件。

| 概念 | 含义 |
|---|---|
| **发送信号** | 内核/进程把信号发给目标进程 |
| **接收信号** | 目标进程对信号作出反应 |
| **待处理（Pending）** | 已发送但尚未被接收 |
| **阻塞（Blocked）** | 暂时不接收某信号（仍待处理） |

**信号的三种处理方式**：
1. **默认行为**（终止、忽略、停止、继续）
2. **忽略**（`SIG_IGN`）
3. **自定义处理程序**（`signal` / `sigaction`）

### 8.6.2 常用信号

| 信号 | 默认行为 | 说明 |
|---|---|---|
| `SIGINT` | 终止 | Ctrl-C |
| `SIGTSTP` | 停止 | Ctrl-Z |
| `SIGKILL` | 终止 | **不可捕获/阻塞** |
| `SIGSTOP` | 停止 | **不可捕获/阻塞** |
| `SIGSEGV` | 终止 | 段错误 |
| `SIGCHLD` | 忽略 | 子进程停止/终止 |
| `SIGALRM` | 终止 | 定时器 |
| `SIGPIPE` | 终止 | 写已关闭管道 |

### 8.6.3 发送信号

- `kill(pid, sig)`：向进程发信号
- `alarm(sec)`：`sec` 秒后发 `SIGALRM`
- `raise(sig)`：向自己发信号

### 8.6.4 接收与处理

```c
signal(SIGINT, handler);                  // 简单但不可移植
sigaction(SIGINT, &act, NULL);            // 推荐，语义清晰
```
- **处理程序在"信号上下文"中运行**，可被其他信号打断
- 处理程序返回后，回到被中断的指令继续执行

### 8.6.5 阻塞与解除阻塞

```c
sigprocmask(SIG_BLOCK, &mask, &oldmask);   // 阻塞
sigprocmask(SIG_UNBLOCK, &mask, NULL);     // 解除
```
- 用 `sigemptyset` / `sigaddset` 构造信号集
- **阻塞的信号不会丢失**，解除后会递送一次（同类信号合并）

### 8.6.6 信号安全与竞态 ⚠️

⚠️ **关键原则**
1. **处理程序要尽量简单**，只做标记（设置 `volatile sig_atomic_t` 标志）
2. **只调用异步信号安全函数**（`write` 是安全的，`printf`/`malloc` **不是**）
3. **避免竞态**：用 `sigprocmask` 保护临界区
4. **不要用 `signal` 处理 `SIGCHLD` 时忘记回收**，否则产生僵尸

📌 **典型竞态**：父进程在 `fork` 后、`waitpid` 前收到 `SIGCHLD`；应用 `sigprocmask` 先阻塞再操作。

---

## 本章速记

- 异常四类：**中断（异步）/ 陷阱（系统调用）/ 故障（缺页，可重试）/ 终止（不返回）**
- 进程 = 逻辑控制流 + 私有地址空间；用户态/内核态切换
- `fork` 调用一次返回两次；用 **COW**；$n$ 次 fork → $2^n$ 进程
- `execve` **不返回**；`waitpid` 回收子进程，防僵尸
- shell = **fork + execve + waitpid**
- 信号：**待处理 vs 阻塞**；处理程序要简洁、只用异步信号安全函数
