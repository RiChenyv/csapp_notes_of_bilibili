# 第 5 章 优化程序性能

> 对应课程：短系列 5-1 ~ 5-6（6P）｜直播版 P18 ~ P20
> 本章讲**怎么写快代码**：先消除编译器无法自动做的低效，再理解现代处理器的并行能力，用循环展开与多累加器榨干性能。

---

## 5.1 优化的一般方法论

### 5.1.1 编译器能做什么、不能做什么

**编译器会做的优化**
- 常量折叠、公共子表达式消除
- 强度削弱（乘法→移位）
- 简单循环优化

**编译器不敢做的优化**（⚠️ 重点：这些是程序员要手动做的）
| 障碍 | 原因 |
|---|---|
| **内存别名（Memory Aliasing）** | 两个指针可能指向同一位置，改动顺序会改变语义 |
| **函数副作用** | 不知道函数有无副作用，不敢消除调用 |
| **复杂度限制** | 编译器不做激进的循环变换 |

📌 **典型例子**：先用局部变量把内存里的值取出来算，最后写回 —— 因为编译器不敢假定 `*dest` 和 `*src` 不重叠。
```c
// 慢：每次循环都读写内存
for (i = 0; i < n; i++) *dest += a[i];
// 快：用局部累加
int acc = *dest;
for (i = 0; i < n; i++) acc += a[i];
*dest = acc;
```

### 5.1.2 性能度量：CPE

**CPE（Cycles Per Element）**：处理每个元素的平均时钟周期数。**CPE 越小越快**。
- 相同 CPE 的代码，处理 n 个元素用时 $\approx \text{CPE} \times n + \text{常数}$
- 用 CPE 比较不同实现的优劣

## 5.2 现代处理器（微体系结构）

### 5.2.1 超标量（Superscalar）与乱序（Out-of-Order）

- **超标量**：一个周期发射多条指令
- **乱序执行**：不按程序顺序执行，只要数据依赖满足
- **指令流水线**：更深的流水（15~20 级）

**乱序处理器的两大部件**
- **指令控制单元（ICU）**：取指、译码、发射
- **执行单元（EU）**：多个功能单元（ALU、加载、存储、浮点……）

### 5.2.2 关键概念

| 概念 | 含义 |
|---|---|
| **发射时间（Issue time）** | 两条同类指令之间的最小周期数（受功能单元数量限制） |
| **延迟（Latency）** | 一条指令从开始到结果可用的周期数 |
| **容量（Capacity）** | 功能单元可同时进行的操作数 |
| **关键路径（Critical Path）** | 数据依赖图中最长路径，决定程序延迟下界 |

💡 **性能瓶颈 = max(延迟限制, 吞吐量限制)**。当运算延迟高时，需要**并行**来填满流水线。

### 5.2.3 寄存器重命名

- 处理器用**物理寄存器**消除假依赖（WAR/WAW），只保留真依赖（RAW）
- 使乱序执行更自由

## 5.3 数据流图与循环优化

### 5.3.1 数据流图（Data-Flow Graph）

- 节点 = 运算，边 = 数据依赖
- 只画**影响结果的依赖**（不画内存地址计算，因为可并行）
- 用于分析**关键路径**和可并行性

### 5.3.2 循环展开（Loop Unrolling）⚠️

把循环体复制 k 次，减少循环开销（判条件、增计数）：
```c
for (i = 0; i < n; i += 2) {   // 2 路展开
    acc = (acc + a[i]) + a[i+1];
}
```
**收益**：减少分支、增加编译器调度空间。
**局限**：单纯展开**不改变关键路径**（乘加链仍是串行依赖）。

### 5.3.3 提高并行性：多个累加器 ⚠️

```c
// 关键路径长：acc 串行依赖
for (...) acc = acc * a[i];

// 2 路并行：两条独立依赖链，吞吐翻倍
for (...) { acc0 = acc0 * a[i]; acc1 = acc1 * a[i+1]; }
```
- 因为浮点乘法满足结合律**在数学上**，可以打破依赖（但会改变舍入结果，需程序员同意）
- 展开 + 多累加器 → 逼近**吞吐量极限**（受发射时间限制）

📌 **达到极限后**：再展开无收益，瓶颈转为功能单元发射时间。

### 5.3.4 重新结合变换

把 `acc = (acc + a[i]) + a[i+1]` 写成 `acc = acc + (a[i] + a[i+1])`，可缩短关键路径（先并行算括号内）。

## 5.4 优化内存性能

- **加载（load）**：从内存取数据到寄存器
- **存储（store）**：写回内存
- 现代 CPU 每周期可做 2 次加载 + 1 次存储，但**加载-存储单元是有限资源**

**优化要点**
- 把**循环不变量**提到循环外（代码移动）
- 用局部变量减少内存访问
- 顺序访问、利用局部性（跨到第 6 章）
- 写操作会阻碍乱序（处理器必须保证内存一致性）→ 尽量少写

---

## 5.5 其他优化技术

| 技术 | 说明 |
|---|---|
| **代码移动** | 把计算提到循环外（若结果不变） |
| **消除不必要的内存引用** | 用局部变量 |
| **减少过程调用** | 内联（inline），避免栈开销 |
| **消除不必要的函数调用** | 去掉重复计算的调用 |
| **条件传送（cmov）** | 替代分支，避免分支预测错误惩罚 |
| **写缓冲/预取** | 硬件层面 |

⚠️ **条件传送 vs 分支**：`cmov` 无论条件如何都计算两边的值，避免了分支预测失败的惩罚；但若表达式有副作用或代价高，反而变慢。

**Amdahl 定律**（再次强调）：$S = 1 / ((1-\alpha) + \alpha/k)$，优化要抓**热点**（Profiling 找瓶颈）。

---

## 本章速记

- 编译器受**内存别名**和**函数副作用**限制，关键优化靠人工
- **CPE** 衡量性能；瓶颈 = max(延迟, 吞吐)
- 循环展开减少开销；**多累加器**打破依赖链提高并行
- 优化内存：代码移动、少访存、利用局部性
- **条件传送**避免分支预测错误；用 Profiling 定位热点
