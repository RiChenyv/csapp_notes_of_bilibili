# 第 10 章 系统级 I/O

> 对应课程：直播版 P41 ~ P42（短系列未单独投稿）
> 本章讲**Unix I/O 模型**：文件描述符、read/write、RIO 包、文件共享与重定向。是理解"一切皆文件"与网络编程的基础。

---

## 10.1 Unix I/O

### 10.1.1 一切皆文件

**Unix I/O 的核心思想**：把设备（磁盘、键盘、网络、终端）统一抽象为**文件**，操作统一。

| 文件类型 | 说明 |
|---|---|
| **普通文件（Regular file）** | 包含任意数据的字节序列，有目录项 |
| **目录（Directory）** | 包含一组链接（link）的文件，每个链接指向一个文件 |
| **套接字（Socket）** | 与另一个进程通信的通道（网络） |
| **命名管道/设备等** | 特殊文件 |

### 10.1.2 打开的文件 = 文件描述符

- **文件描述符（File Descriptor, FD）**：小的非负整数，进程通过它引用文件
- 每个进程默认打开三个：

| FD | 名称 | 常量 |
|---|---|---|
| 0 | 标准输入 | `STDIN_FILENO` |
| 1 | 标准输出 | `STDOUT_FILENO` |
| 2 | 标准错误 | `STDERR_FILENO` |

### 10.1.3 核心系统调用

```c
int open(const char *filename, int flags, mode_t mode);  // 打开，返回 fd
int close(int fd);                                        // 关闭
ssize_t read(int fd, void *buf, size_t n);               // 读，返回读到的字节数
ssize_t write(int fd, const void *buf, size_t n);        // 写，返回写入字节数
off_t lseek(int fd, off_t offset, int whence);           // 定位
```
⚠️ **返回值**
- `read`/`write` 返回**实际传输的字节数**，**可能小于请求的字节数**（short count）——必须循环处理！
- `read` 返回 0 表示 **EOF**；返回 -1 表示错误
- `open` 的 `flags`：`O_RDONLY/O_WRONLY/O_RDWR`、`O_CREAT`、`O_TRUNC`、`O_APPEND`

📌 **短计数（short count）出现的情况**：读终端、读写网络套接字、被信号中断、到达 EOF。

## 10.2 RIO（Robust I/O）包

**目的**：自动处理短计数，提供可靠的读写。

| 函数 | 用途 |
|---|---|
| `rio_readn` / `rio_writen` | **无缓冲**，循环读写直到满足 n 字节（或 EOF/错误） |
| `rio_readlineb` | **带缓冲**，读一行（到 `\n`） |
| `rio_readnb` | **带缓冲**，读 n 字节 |

**带缓冲的意义**：减少系统调用次数（每次读一大块进缓冲区），大幅提升小数据读取效率。

**RIO 结构**：`rio_t` 含缓冲区、当前位置、剩余字节数、fd。

## 10.3 文件元数据与 stat

```c
int stat(const char *filename, struct stat *buf);
int fstat(int fd, struct stat *buf);
```
**`struct stat` 关键字段**：`st_mode`（文件类型+权限）、`st_size`（大小）、`st_uid`/`st_gid`、`st_ino`（inode 号）。

**判断文件类型宏**：`S_ISREG`（普通）、`S_ISDIR`（目录）、`S_ISSOCK`（套接字）……

## 10.4 共享文件与重定向 ⚠️⚠️

### 10.4.1 三张表

Unix 内核用三个数据结构描述打开的文件（⚠️ 高频）：

| 表 | 内容 | 生命周期 |
|---|---|---|
| **描述符表（Descriptor Table）** | 每进程一张，FD → 文件表项指针 | 进程 |
| **文件表（Open File Table）** | 打开文件的集合：**文件位置、引用计数、v-node 指针** | 系统级，所有进程共享 |
| **v-node 表** | 文件元数据（stat 信息） | 系统级 |

```
进程A: fd0 ─┐
进程A: fd1 ─┼─> 文件表项(位置/引用计数) ─> v-node(元数据)
进程B: fd3 ─┘
```
💡 两个 FD 共享同一文件表项 $\Leftrightarrow$ 共享**文件位置**（如 `fork` 后父子进程）；若各自 `open` 同一文件则得到**不同**文件表项，位置独立。

### 10.4.2 重定向（dup2）⚠️

```c
int dup2(int oldfd, int newfd);   // 让 newfd 指向 oldfd 所指的文件表项
```
- **I/O 重定向**：`dup2(fd, STDOUT_FILENO)` 把标准输出改到 `fd`
- shell 的 `>` 就是 `open` + `dup2` + `close` 实现的

**shell 重定向实现**：
```c
int fd = open("out.txt", O_WRONLY|O_CREAT|O_TRUNC, 0644);
dup2(fd, STDOUT_FILENO);   // 1 号 fd 现在指向 out.txt
close(fd);
execve(...);               // 程序输出到文件
```

## 10.5 I/O 与网络、性能

- **网络套接字**也是文件，可用 `read`/`write`（也可以用 `rio_*`）
- 标准 I/O（`printf`/`fgets`）在**网络 I/O** 上有问题：缓冲可能导致读写不全、协议边界错乱 → 推荐用 **RIO** 处理套接字
- **系统调用开销**：每次 `read`/`write` 都陷入内核，昂贵 → 带缓冲减少调用次数
- **文件元数据（stat）** 与 **目录**（`readdir`）操作

💡 **现代 I/O 趋势**：`mmap`（零拷贝）、`sendfile`（内核内直接传输）、IO 多路复用（`select`/`poll`/`epoll`）——属于网络编程范畴（CSAPP 第 11 章，本课程未覆盖）。

## 本章速记

- **一切皆文件**；FD 0/1/2 = 标准输入/输出/错误
- `read`/`write` 可能**短计数**，必须循环 → 用 **RIO** 包
- 共享文件三张表：**描述符表（每进程）+ 文件表 + v-node 表**
- `fork` 后父子**共享文件位置**；各自 open 则独立
- **`dup2` 实现 I/O 重定向**（shell 的 `>`）
- 网络 I/O 用 RIO，不要用标准 I/O 的缓冲区
